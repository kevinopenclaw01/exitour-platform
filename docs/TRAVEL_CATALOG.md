# 여행 카테고리 개편 (2026-10-22)

## 공개 구조

- `/`: 두 가지 여행 방식 선택, 나라·도시 선택, 비교, 상담, FAQ.
- `/packages`: **우리끼리 맞춤 패키지**. 우리 그룹 전담 가이드, 일정·동선 맞춤. 현지인 또는 한국어 가능 가이드. 호텔·항공 기본 불포함, 요청 시 예약 대행 상담.
- `/activities`: **내맘대로 단품 투어**. 여행 전체 전담 가이드 없이 개별 서비스를 선택. 기사·현장 안내 여부는 서비스별 조건에 따름.
- `/{category}/{countrySlug}/{citySlug}`: 지역 안내와 상담 페이지. 확정 상품이나 예약 페이지가 아님.

우리끼리 맞춤 패키지: 베트남(다낭·나트랑·사파·푸꾸옥), 카자흐스탄(알마티), 필리핀(보홀·보라카이).

내맘대로 단품 투어: 베트남(다낭·푸꾸옥), 필리핀(보홀·보라카이), 괌.

## 기존 상품 보존과 노출 중단

기존 `lib/data.ts`, mock, 상품 상세 소스, 이미지, 가격 계산 코드와 DB는 삭제하거나 수정하지 않았다. 홈과 메뉴에서 기존 상품·호텔·확정 요금 노출을 제거했다.

`lib/travel/legacyRoutes.ts`를 `next.config.ts`에서 사용해 기존 상품·목록·가이드 주소를 새 카테고리로 **307 임시 이동**시킨다. 예전 직접 링크나 검색 결과로 들어와도 구상품은 표시되지 않는다. 사파는 `/packages/vietnam/sapa`, 카자흐스탄은 `/packages/kazakhstan/almaty`로 안내한다. 영구 리디렉션이 아니므로 검수 후 기존 상세 URL을 다시 열 수 있다.

빌드 결과에 구페이지가 남는 것은 보존 목적이다. HTTP 진입은 리디렉션이 먼저 처리한다. 운영 경로 `/quote`, `/api/quote`, `/admin`에는 리디렉션을 적용하지 않는다.

## 다음 상품 등록

1. 먼저 카테고리와 나라·도시를 정한다. 공개 지역 데이터의 원본은 `lib/travel/catalog.ts`다.
2. 사파·카자흐스탄의 기존 일정·자료를 재사용하되 호텔·항공 불포함, 가이드 언어, 그룹 전용 여부와 실제 요금을 새 기준으로 재검수한다.
3. 상품 상세를 검수한 뒤 해당 상품만 공개 목록에 추가하고, 해당 경로의 임시 이동만 해제한다. 넓은 경로 규칙이 후속 상품을 가리지 않도록 구체적인 규칙으로 좁힌다.
4. 단품 상품을 맞춤 패키지와 섞지 않는다. 모든 단품에 가이드·차량·식사가 있다고 일반화하지 않는다.
5. 승인 전 원가·마진·예전 가격·후기·재고를 공개하지 않는다.

## 상담과 운영

기존 `buildQuoteUrl`을 그대로 사용한다. `destination`, `service`, `sourcePath`를 전달하며, 아직 개별 상품이 없는 지역 상담에 가상의 `productId`를 만들지 않는다.

견적 폼·API·Supabase·관리자·RLS·카카오톡 알림은 수정하지 않는다.
